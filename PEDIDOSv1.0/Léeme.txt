✨ PEDIDOS v1.0 - Sistema de Gestión de Empresas y Vendedores ✨


📋 DESCRIPCIÓN DEL PROGRAMA

Este programa implementa un sistema de gestión de pedidos para empresas con múltiples sucursales y diferentes tipos de vendedores. Permite crear empresas, sucursales y tres categorías de vendedores (particulares, profesionales y empresas), demostrando polimorfismo y herencia en C++.

🎯 ¿CÓMO FUNCIONA?

1. 🚀 INICIALIZACIÓN: El programa inicia con un encabezado visual y configura la consola UTF-8.
2. 🏢 EMPRESA: Crea una empresa con nombre personalizado.
3. 📍 SUCURSAL: Agrega una sucursal con nombre y dirección.
4. 👥 VENDEDORES: Crea 3 vendedores de tipos diferentes (Particular, Profesional, Empresa).
5. 💼 TRABAJO: Demuestra polimorfismo haciendo trabajar a cada vendedor según su especialización.
6. 📊 RECORRIDO: Muestra datos completos de cada vendedor usando polimorfismo.
7. 📢 NOTIFICACIONES: Envía mensajes a todos los vendedores de la sucursal.
8. 🧹 LIMPIEZA: Libera toda la memoria utilizada correctamente en orden inverso.

🔗 RELACIONES ENTRE CLASES

• Empresa → Sucursal (Agregación Pura - array dinámico de punteros).
• Sucursal → Empleado (Agregación Pura - array fijo de 10 punteros).
• Empleado ← VendedorParticular (Herencia Pública).
• Empleado ← VendedorProfesional (Herencia Pública).
• Empleado ← VendedorEmpresa (Herencia Pública).

🔧 PROCEDIMIENTO DE COMPILACIÓN

Desde la carpeta raíz PEDIDOSv1.0/, ejecutar:

1. Compilar todos los archivos .cpp:

g++ -I include/ src/*.cpp -o bin/Pedidos.exe

2. Ejecutar el programa:

bin\Pedidos.exe

⚠️ NOTA: Es necesario usar compilador compatible con C++11 o superior.

🎨 CARACTERÍSTICAS PRINCIPALES

✅ PROGRAMACIÓN ORIENTADA A OBJETOS:
   • Clase abstracta (Empleado) con métodos virtuales puros.
   • Herencia pública entre Empleado y tipos de Vendedores.
   • Polimorfismo completo en métodos trabajar(), mostrarDatos(), calcularSalarioTotal().
   • Encapsulación estricta con atributos privados/protegidos.

✅ GESTIÓN DE MEMORIA:
   • Uso de punteros dinámicos (new/delete).
   • Arrays dinámicos redimensionables para sucursales.
   • Array fijo de 10 punteros para vendedores por sucursal.
   • Liberación ordenada de memoria en destructores.

✅ DISEÑO UML IMPLEMENTADO:
   • Empresa (1) → (N) Sucursal (Agregación).
   • Sucursal (1) → (N) Empleado (Agregación).
   • Empleado (1) ← (3) Tipos de Vendedores (Herencia).

✅ INTERFAZ DE USUARIO:
   • Emojis UTF-8 para mejor visualización.
   • Formato de salida organizado con separadores.
   • Entrada interactiva para datos de vendedores.
   • Configuración automática de consola Windows.

✅ CUMPLIMIENTO DE CONSIGNA:
   • 3 vendedores de diferentes tipos (Punto 5).
   • Implementación completa con punteros (Punto 6).
   • Recorrido polimórfico mostrando salario, área y datos (Punto 7).
   • Clase Empleado abstracta con métodos virtuales puros (Punto 3).

📝 ESPECIFICACIONES TÉCNICAS

• CAPACIDADES:
   - Empresa: Sucursales dinámicas (redimensionable).
   - Sucursal: 10 vendedores máximo (array fijo).
   - Vendedores: 3 tipos diferentes con bonos específicos.

• BONOS POR TIPO:
   - Particular: +$150 si tiene vehículo propio.
   - Profesional: +$300 por matrícula profesional.
   - Empresa: +$250 por representar empresa.

• REQUISITOS DE ENTRADA:
   - Vendedor Particular: Confirmación de vehículo propio (s/n).
   - Vendedor Profesional: Matrícula profesional (ej: MP-1234).
   - Vendedor Empresa: Razón social de la empresa.

⚠️ LIMITACIONES CONOCIDAS

• Capacidad fija de 10 vendedores por sucursal.
• No incluye persistencia de datos (solo en memoria).
• Interfaz por consola (no gráfica).
• Solo una sucursal implementada en el Main.cpp demo.

🚀 DEMOSTRACIÓN DE FUNCIONALIDADES

El Main.cpp implementa una demostración "hardcore" que muestra:

1. Creación de empresa y sucursal con punteros.
2. Entrada interactiva para 3 vendedores diferentes.
3. Polimorfismo: cada vendedor trabaja de manera única.
4. Recorrido polimórfico mostrando datos específicos por tipo.
5. Cálculo de salarios con bonos según especialización.
6. Sistema de notificaciones para todos los vendedores.
7. Liberación ordenada de memoria.
